Whatnot whatnot://test-login forced-logout PoC

Unauthenticated deep link → single-tap session termination in the production Android app.

Authorized security research. This page is a reproduction aid for a HackerOne bug bounty report against Whatnot. It contains no exploit, no credentials, and no data collection. All values are inert placeholders. If you are not a researcher, you do not need to run this.

1. Trigger the forced logout

The values below are arbitrary and are never validated by the app — the handler only checks that the u and p parameters are present. Any non-empty value works.

RECOMMENDED — intent:// auto-launches the app
Tap to force logout intent://test-login?u=hackerone_probe&p=hackerone_probe_pw&e=prod#Intent;scheme=whatnot;package=com.whatnot_mobile;end
ALTERNATIVE — bare whatnot:// scheme
Tap to force logout (bare scheme) whatnot://test-login?u=hackerone_probe&p=hackerone_probe_pw&e=prod

Note: Android Chrome blocks script-initiated navigation to custom schemes without a user gesture, so auto-redirect frequently does nothing. The tap-target buttons above are the reliable path, and are also deliberate so this page cannot be used as a drive-by.

2. Verify the session was actually destroyed

  1. Tap a button above while logged in on the home feed.
  2. You are taken straight to the sign-in screen with the fields pre-filled. No confirmation prompt.
  3. Exit the app completely (Back / swipe away) and relaunch Whatnot from the home-screen icon.
  4. The app opens to the logged-out welcome screen.

Step 4 is the one that matters. It distinguishes a genuine server-side session destruction from a cosmetic screen change sitting on top of an unaffected session.

3. adb alternative (phone attached over USB)

Deterministic, and needs no browser in the loop:

adb shell "am start -a android.intent.action.VIEW -c android.intent.category.BROWSABLE -d 'whatnot://test-login?u=hackerone_probe&p=hackerone_probe_pw&e=prod'"

If you run it without the surrounding quotes, the remote shell splits on &, the parameters are silently dropped, and the link appears to do nothing.

What this demonstrates

  • AndroidManifest.xml registers test-login as a BROWSABLE host on the exported MainActivity.
  • The only gate is e == BuildConfig.ENVIRONMENT_NAME, which is the literal string "prod" in this build.
  • u and p are checked for presence only, never validated against the server.
  • The handler calls Authenticator.logout(...) unconditionally before navigating to the pre-filled sign-in screen.
